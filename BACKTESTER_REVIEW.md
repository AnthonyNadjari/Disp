# Dispersion Backtester — Final Review

## 1. Verdict

**Not fully correct — do not trust reported P&L in three configurations.** The core payoff math (variance/vol-swap arithmetic, corridor barriers, var→vol conversion) and the O(n) window refactor are sound, and the happy-path cross-corridor leg construction/sign is right. But four confirmed defects corrupt *delivered* results in specific-but-reachable setups: (a) when the corridor stock fails to load, every affected leg silently becomes a plain long-index-variance swap mislabelled as the stock's dispersion leg — a whole-basket regime change with no warning; (b) a set `end_date` bounds the GA's scoring window but is ignored by the returned backtest, leaking post-cutoff data into the curve and metrics the user sees; (c) rolling kernels emit stale P&L on no-trade/NaN rows, defeating `DROP_INCOMPLETE_DAYS` and desyncing `leg.metrics` from the scored matrix; (d) cross-corridor short legs are subtracted by the backtester but added by the optimizer. None of these is a math error — they are silent failure-mode and windowing defects — which is exactly why they are dangerous: the numbers look fine and reconcile only by accident. Fix the cross-corridor fallback and `end_date` handling before relying on out-of-sample or cross-corridor results.

## 3. Performance / time

Kernels are correctly `@nb.jit(nopython=True, cache=True)`; the GA does **not** rebuild the matrix per generation (`_ts_mat`/`_valid_mask` built once, `_optimizer.py:378-384`); memory is a non-issue. The wins are duplicated/quadratic passes, all one-time (not inside the GA loop):

- **Corridor kernel is O(n²) per leg** (`_backtester.py:154-160`) — the linear valid-index scan the vol-swap kernel already replaced with `cum_valid`. VAR_SWAP_CORRIDOR is the default product. ~4M vs ~2000 iterations/leg at ~2000 rows. **Fix:** copy the exact `cum_valid` construction from `_rolling_pnl_volswap`; identical windows, O(1) lookup. Safe, behaviour-preserving.
- **Winner backtest recomputes P&L for the full candidate universe** (`_api.py:1153-1164` → `_compute_all_pnl` iterates all `leg_map.keys()`), then zeroes non-basket legs by weight — despite the "free" comment. ~10 winners vs 50-100+ candidates. **Fix:** filter `legs` to basket keys (`long_basket`/`short_basket`) before `run_from_optimization`; output identical. (Can't reuse the built matrix verbatim — it used the sliced/warm-up window.)
- **Per-leg metrics pass duplicates kernel work during "Loading data"** (`_backtester.py:847-881` `_compute_metrics` vs `_api.py:586` `_build_pnl_matrix`). Combined with the winner pass, a mono leg's kernel runs up to **3× per optimize()**. **Fix:** derive per-leg metrics by slicing the matrix `_build_pnl_matrix` already produces.
- **Streamlit cache decorator rebuilt every call** (`_backtester.py:701-710`): `@st.cache_data`-wrapping an inner `_fetch` on each invocation can weaken/bypass the cross-rerun cache → same Bloomberg batch refetched (seconds each, the real "Loading data" cost). **Fix:** hoist `_fetch` to module scope, decorate once; narrow `except (ImportError, Exception)` to `except ImportError` so genuine errors aren't swallowed into a refetch.
- Minor: `_build_active_mask` is a pure-Python row loop despite a "vectorized" docstring (`_backtester.py:226-254`) — once per backtest, ~20k iters, low impact; njit or fix the docstring.

Rough impact: fixing the corridor kernel + winner-legs filter removes the two hottest, most-quadratic passes and roughly halves kernel time on the default product path; the Streamlit cache fix targets the dominant *perceived* load time.

## 4. Robustness

- **Bloomberg failure is silent** (§2, med) — collapse infra failure vs empty universe into distinguishable outcomes.
- **NaN mono strike silently drops/wipes legs** (§2, med) — validate finiteness at parse time; note the asymmetry that cross strikes already are validated.
- **`run_backtest()` None strike** (`_backtester.py:926`): `strikes.get(t)` → `None` reaches the njit kernel (`strike: float`) as a cryptic numba TypeError instead of "missing strike for X." Masked today by the constructor crash; surfaces once that's fixed. Default+validate.
- **Non-positive final price → `inf`** (§2, low) — guard the numerator.
- **DROP over-drops to shortest common history with no floor** (`_backtester.py:577` vs `_optimizer.py:1392-1394`): one recently-listed/illiquid name truncates all legs to the intersection; backtester has no `min_valid_days` guard the optimizer has, so it can emit a handful-of-rows curve where the optimizer would refuse. Document the intersection behaviour; consider mirroring the floor.

## 5. Flexibility

- **`SwapConfig.end_date` is documented but ignored by the backtester** (`models.py:154`) — same root cause as the §2 HIGH look-ahead bug; the optimizer honours it, the backtester doesn't. Inconsistent contract; fixing §2 fixes this.
- **Grace is a phantom config knob** (`reweight_grace_days`, default 3) — advertises smoothing that doesn't exist. Either wire it up (both engines) or remove it.
- **Hardcoded magic numbers** (`_backtester.py:762,296-297`): warm-up `buffer_days = int(n_exp*365/252)+30` has no config knob; `run()`'s default window is `today-20y` while the docstring says "5 years ago" and `config.lookback_years` is ignored on that path (a no-op only because fetched history is shorter). Derive the default from `config.lookback_years`; expose the buffer grace; fix the docstring.

## 6. Recommended next steps (highest value, ordered)

1. **Kill the cross-corridor silent fallback** (`_api.py:315-317`, `_backtester.py:501-505`) — skip/drop the leg and emit `warnings.warn` when the corridor stock is missing; never substitute an index swap. *Highest-impact correctness fix: prevents a whole basket silently becoming long index variance.*
2. **Apply `end_date` in the backtest** — add the param to `run`/`run_from_optimization`, mask `<= end_date` alongside the start filter (`_backtester.py:366-368`), thread from `_api.py:1163-1164`. Closes the reported-metrics look-ahead. Small, post-computation row filter only.
3. **Make kernel `~isnan` mean "traded today"** (`_backtester.py:118-121,154-160`) — require the current row valid before writing `out[i]`. Restores `DROP_INCOMPLETE_DAYS` and reconciles matrix vs `_compute_metrics`.
4. **Unify the cross-corridor short sign** (`_backtester.py:656/322` ↔ `_optimizer.py:1419`) — one convention, plus a cross-corridor-short regression test asserting `optimizer net_pnl == backtest Result`.
5. **Port `cum_valid` into `_rolling_pnl_corridor` and filter winner legs before backtest** (`_backtester.py:154-160`; `_api.py:1153-1164`) — two safe, behaviour-preserving edits that remove the quadratic default-path kernel and the redundant full-universe recompute.

*Also worth a quick pass while in these files:* validate finite mono strikes at parse time (§4), and decide grace's fate — wire it into both engines or delete it (§2/§5).
